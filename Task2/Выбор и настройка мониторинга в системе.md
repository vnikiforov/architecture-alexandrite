
# План внедрения системы мониторинга для ИС "Александрит"

## 1. Мотивация

С момента появления API для оформления заказов, традиционные метрики Яндекс.Метрики перестали отражать полную картину работы системы.

**Проблемы без мониторинга:**

* 40-50% транзакций через API остаются "невидимыми"

* Позднее обнаружение проблем (клиенты сообщают раньше техперсонала)

* Сложность диагностики сбоев

* Невозможность прогнозирования узких мест

* Ухудшение клиентского опыта

**Преимущества внедрения:**

* Сокращение времени простоя на 30-40%

* Улучшение SLA с 95% до 99.5%

* Раннее обнаружение проблем

* Обоснованное масштабирование ресурсов

* Снижение эксплуатационных расходов на 20-25%

## 2. Выбор подхода к мониторингу

**Гибридный подход**:

|Компонент|Подход|Обоснование|
|-|-|-|
|API-сервисы|Четыре золотых сигнала|Оптимально для измерения качества сервиса|
|БД, RabbitMQ|USE-метод|Фокусировка на ресурсах инфраструктуры|
|Бизнес-процессы|RED-метод|Отслеживание бизнес-транзакций|

**Четыре золотых сигнала для API**:

1. Задержка (Latency)

2. Трафик (Traffic)

3. Ошибки (Errors)

4. Насыщенность (Saturation)

**USE-метод для инфраструктуры**:

1. Использование (Utilization)

2. Насыщенность (Saturation)

3. Ошибки (Errors)

**RED-метод для бизнеса**:

1. Частота (Rate)

2. Ошибки (Errors)

3. Длительность (Duration)

## 3. Метрики для мониторинга

RabbitMQ (**USE-метод**)

|Метрика|Зачем нужна|Ярлыки|Критичность|
|-|-|-|-|
|Number of dead-letter-exchange letters in RabbitMQ|Показывает необработанные сообщения|queue_name, exchange_name, reason|Высокая|
|Number of message in flight in RabbitMQ|Насыщенность очереди|queue_name, consumer_count|Высокая|


Дополнительные метрики:

* Queue length per queue

* Message publish rate

* Consumer utilization

API Сервисы (**Четыре золотых сигнала**)

|Метрика|Зачем нужна|Ярлыки|Критичность|
|-|-|-|-|
|Number of requests (RPS) for internet shop API|Отслеживание нагрузки|endpoint, method, user_type|Средняя|
|Response time (latency) for shop API|Качество обслуживания|endpoint, method, percentile|Высокая|
|Number of HTTP 500 for shop API|Стабильность системы|endpoint, method, error_type|Высокая|
|CPU % for shop API|Загрузка ресурсов|instance, pod, deployment|Высокая|

Дополнительные метрики для API:

* Request duration histogram

* Apdex score

* Business transaction success rate

Базы данных (**USE-метод**)

|Метрика|Зачем нужна|Ярлыки|Критичность|
|-|-|-|-|
|Memory Utilization for shop db instance|Использование памяти|instance_type, environment|Высокая|
|Number of connections for shop db instance|Ограничение подключений|user, application|Высокая|
|Size of shop db instance|Планирование емкости|table_schema, table_name|Средняя|

Хранилище S3 (**USE-метод**)

|Метрика|Зачем нужна|Ярлыки|Критичность|
|-|-|-|-|
|Size of S3 storage|Контроль хранения 3D-файлов|bucket, file_type, project_id|Средняя|

Бизнес-метрики (**RED-метод**)

|Метрика|Зачем нужна|Ярлыки|Критичность|
|-|-|-|-|
|Number of simultaneous sessions for shop API|Активность пользователей|user_type, region|Низкая|
|Kb transferred (received) for shop API|Анализ трафика|endpoint, content_type|Низкая|

## 4. План действий

### Фаза 1: Подготовка (1-2 недели)

Задачи:

1. Анализ текущей инфраструктуры

    * Инвентаризация серверов и сервисов

    * Определение точек интеграции

2. Выбор инструментов мониторинга

    * Prometheus + Grafana для метрик

    * ELK Stack для логов

    * Jaeger для трассировки

3. Разработка MVP дашбордов

    * Основные метрики доступности

    * Ключевые бизнес-показатели

### Фаза 2: Внедрение (3-4 недели)

Задачи:

1. Настройка сбора метрик

    * Установка и конфигурация Prometheus

    * Интеграция с существующими сервисами

    * Настройка экспортеров для БД и RabbitMQ

2. Создание основных дашбордов

    * Обзор системы

    * Детали по компонентам

    * Бизнес-метрики

3. Настройка алертинга

    * Определение пороговых значений

    * Настройка уведомлений (Slack, Email, Telegram)

### Фаза 3: Оптимизация (постоянно)

Задачи:

1. Доработка метрик

    * Добавление бизнес-метрик

    * Оптимизация запросов

    * Настройка retention политик

2. Обучение команды

    * Работа с Grafana

    * Анализ метрик

    * Реакция на алерты

## 5. Показатели насыщенности и обработка превышений

### RabbitMQ

* Порог: 1000 сообщений в очереди / 50 сообщений в dead-letter

* Действия при превышении:

    1. Автоматическое масштабирование воркеров

    2. Оповещение команды поддержки

    3. Временное ограничение приема новых заказов

    4. Запуск процедуры очистки dead-letter

### API Сервисы

* Порог: 90% CPU / 85% памяти / p95 latency > 5s

* Действия при превышении:

    1. Автоматическое горизонтальное масштабирование

    2. Балансировка нагрузки между инстансами

    3. Отключение неключевых функций

    4. Ограничение частоты для внешних вызовов

### Базы данных

* Порог: 80% connections / 90% дискового пространства

* Действия при превышении:

    1. Оповещение DBA для ручного вмешательства

    2. Автоматическая очистка старых логов

    3. Временное ограничение несущественных операций

    4. Запуск процедуры архивации данных

### S3 Хранилище

* Порог: 80% от выделенной квоты

* Действия при превышении:

    1. Автоматическая очистка временных файлов старше 30 дней

    2. Оповещение администратора

    3. Принудительное сжатие старых файлов
